# Документация Dozor Engine

## Принципы

- Сначала фиксируем потребность и границы, затем проектируем решение.
- Отделяем подтверждённые требования от гипотез и технических решений.
- Документируем итеративно, без создания пустых разделов заранее.
- Храним диаграммы в текстовом виде, где это возможно (например, Mermaid или PlantUML).
- Каждый завершённый функциональный сценарий сопровождаем критериями приёмки.

## План артефактов

1. **Vision & Scope** — назначение, пользователи, границы MVP.
2. **Сценарии и требования** — пользовательские действия, функциональные и нефункциональные требования.
3. **Бизнес-правила и состояния** — проверки кодов, переходы, ограничения.
4. **Модель данных** — сущности, связи, ограничения.
5. **Архитектура и интеграции** — компоненты, форматы обмена, безопасность.
6. **Диаграммы и критерии приёмки** — последовательности, состояния, тестируемое поведение.

Файлы по этим разделам создаём по мере обсуждения и согласования, а не заранее.
