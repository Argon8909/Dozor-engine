# User Story Map — Dozor Engine

**Версия:** 0.3  
**Статус:** черновик, сбор требований продолжается

## Жизненный цикл игры

1. Подготовка игры (организатор)
2. Прохождение игры (представитель команды)
3. Проверка результатов (организатор)

| US-08 | Как представитель команды, я хочу видеть текущее задание и вводить найденные коды, чтобы продвигаться по игре. | Требует детализации |
| US-09 | Как представитель команды, я хочу, чтобы система учитывала принятые коды и открывала следующие задания по правилам игры. | Требует детализации |
| US-10 | Как представитель команды, я хочу передать организатору журнал прохождения, чтобы результаты могли быть проверены. | Требует детализации |
| US-16 | Как представитель команды, я хочу заранее загрузить пакет и получить доступ к первому заданию после объявления старта, чтобы начать игру вместе с остальными командами. | Согласовано на уровне сценария |

### Согласованный сценарий старта

1. Команда заранее загружает игровой пакет.
2. До старта приложение ожидает ввода стартового кода и не показывает задание.
3. Организатор объявляет единый стартовый код.
4. Представитель команды вводит его; при корректном коде открывается первое задание её маршрута.
5. Отображаются текст загадки и, при наличии, оценки сложности и опасности.
6. Приложение ожидает дальнейших действий представителя команды.

**Уточнение:** одновременное объявление кода не гарантирует фактически одновременный ввод кода разными командами; доверенная синхронизация времени офлайн не предусмотрена.

### Детализация этапа прохождения (черновик)

|---|---|---|
| US-12 | Как представитель команды, я хочу видеть общее количество основных и бонусных кодов текущего задания раздельно, чтобы понимать объём поиска. | Черновик |
| US-13 | Как представитель команды, я хочу вводить найденный код и получать результат проверки с указанием типа принятого кода, чтобы понимать, засчитан ли он. | Черновик |
| US-14 | Как представитель команды, я хочу видеть раздельный прогресс найденных основных и бонусных кодов, чтобы оценивать прохождение текущего задания. | Черновик |

#### Предварительные критерии приёмки

**US-12**
- При открытии задания отображается количество предусмотренных основных кодов.
- Количество бонусных кодов отображается отдельно.

**US-13**
- Код вводится в специальное поле; система сообщает, принят ли он.
- Для принятого кода указывается тип: основной или бонусный.
- Неверный код не увеличивает счётчики.
- Повторный ввод уже засчитанного кода не увеличивает счётчики.

**US-14**
- Счётчики найденных основных и бонусных кодов отображаются раздельно от общего количества.
- При успешном вводе счётчик соответствующего типа обновляется.
- Прогресс сохраняется между сеансами работы приложения.

**Пока не определены:** условия завершения задания, правила пропуска и влияние бонусных кодов на итоговый результат.

## Границы итераций

**MVP 1:** только текстовое содержимое заданий, офлайн-прохождение, ручные маршруты, коды, защищённые пакеты и журналы.

**Следующая итерация:** изображения и аудиофайлы в заданиях.

## Примечания

- Подробные альтернативные сценарии и исключения будут описываться выборочными Use Case и критериями приёмки.
- Форма интерфейсов, формат пакетов и методы криптографической защиты пока не определены.
- Открытые вопросы приведены в Vision & Scope и будут уточняться по мере анализа.
